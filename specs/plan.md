# План проекта «Вовремя»

> Цель ближайших 6 недель — не выручка, а ответ на вопрос «есть ли спрос».
> Код пишется ровно в объёме, нужном для проверки.

## Фаза 0. MVP для показа (готово, `v0.1.0-alpha`)

| Спека | Результат |
|---|---|
| `001-engine` | движок плана с тестами |
| `002-app-ui` | приложение `/app`, работает офлайн, демо-режим |
| `003-landing` | лендинг `/`, заявки, события, `/admin` |

## Фаза 1. Подготовка к проверке (неделя 1)

1. Деплой на VPS или PaaS с HTTPS (уведомления и PWA требуют HTTPS):
   `docker compose up -d` + обратный прокси (Caddy) с доменом.
2. Задать `PLANER_ADMIN_PASSWORD`, проверить `/admin`.
3. Сделать 2 версии лендинга под сегменты через параметр `?s=events` /
   `?s=adhd` (заголовок и примеры) — задача `005-landing-segments`.
4. Подготовить список из 30–50 контактов на сегмент (см. анализ ниш).

## Фаза 2. Проверка (недели 2–4)

- 15 интервью в B2B (продюсеры мероприятий, фасилитаторы) и 20 — в СДВГ-нише.
- В конце интервью — ссылка на `/app` и просьба провести с ним реальный план.
- Трафик на лендинг: $100–200 таргетированной рекламы + посты в сообществах.
- Еженедельно снимать метрики из `/admin`.

## Валидация: критерии решения (неделя 5)

| Метрика | Продолжать | Менять гипотезу | Остановиться |
|---|---|---|---|
| Посетитель → заявка (целевой трафик) | ≥ 10% | 5–10% | < 5% |
| Посетитель → «Купить» в тарифах | ≥ 3% | 1–3% | < 1% |
| Открыли `/app` → запустили план | ≥ 40% | 20–40% | < 20% |
| Запустили план ≥ 3 раз за 2 недели (из тестеров) | ≥ 40% | 20–40% | < 20% |
| Интервью: описали конкретную боль за 3 мес | ≥ 50% | 30–50% | < 30% |
| Предоплата / письменное намерение (B2B) | ≥ 2 | 1 | 0 |

Решение записывается в `docs/decisions.md` с цифрами.

## Фаза 3. Если «продолжать» (недели 6–12)

Выбирается **одна** ниша.

**B2B (мероприятия/встречи):**
- Экран ведущего / «сцены» по ссылке (read-only, крупный таймер) — синхронизация через сервер (SSE/WebSocket).
- Аккаунты, команды, общий план; жёсткие точки (кофе-брейк, конец аренды) как якоря по часам.
- Оплата: ЮKassa / Stripe, тариф за мероприятие + подписка.

**Личное / СДВГ:**
- Аккаунты и синхронизация; повторяющиеся рутины по расписанию.
- Надёжные уведомления: нативная обёртка (Capacitor) с локальными уведомлениями,
  Live Activities (iOS) / постоянное уведомление (Android).
- Мягкий тон сообщений (проверить A/B), пауза, «переключение» без вины.

## Фаза 4. Если «остановиться»

Зафиксировать выводы, оставить MVP как портфолио, не тратить время на
развитие кода.

## Известные риски

| Риск | Митигация |
|---|---|
| Браузер ограничивает таймеры в фоне, iOS не шлёт уведомления из закрытой вкладки | Время считается по часам; честно предупреждаем в приложении; нативная обёртка в фазе 3 |
| Сжатие воспринимается как давление | Флаг «фиксированный», лимит сжатия, тон сообщений проверяем на интервью |
| Данные только в одном браузере | Экспорт/импорт JSON — задача `006-export` при запросе тестеров |
