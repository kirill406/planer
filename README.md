# Вовремя — планер, который успевает за вас

> Ведёт по плану минута в минуту и при опоздании пересчитывает остаток плана,
> чтобы вы закончили вовремя.

**Статус:** Alpha (`0.1.1-alpha`) — MVP для презентации и проверки спроса.

## Что внутри

| Адрес | Что это |
|---|---|
| `/` | Лендинг: проблема, как работает, живое демо, тарифы, форма раннего доступа |
| `/?s=events`, `/?s=adhd` | Варианты лендинга под сегменты (для рекламы и рассылок) |
| `/app` | Планер (PWA): планы, запуск, строка состояния, уведомления, итоги |
| `/admin` | Воронка спроса и заявки, выгрузка CSV (Basic auth: `admin` + `PLANER_ADMIN_PASSWORD`) |
| `/api/docs` | OpenAPI |

### Как работает планер
- План: пункты с длительностью, время начала **или** «закончить к».
  Пункт можно отметить «фиксированный» — он не сжимается.
- Старт раньше → «Отлично, идём с запасом», пункты идут по заданному времени.
- Старт вовремя → обычный отсчёт.
- Старт позже → «Кажется, мы опаздываем, придётся поторопиться»: оставшиеся
  пункты сжимаются пропорционально (не глубже лимита), чтобы закончить вовремя.
- Время вышло → уведомление, звук, отсчёт опоздания в пункте и в строке состояния.
- После плана → итоги; отклонение больше 10% → предложение сохранить
  сокращённое время, увеличить или разбить пункт на подпункты.

## Быстрый старт

Нужен только [uv](https://docs.astral.sh/uv/) — Python 3.13 он скачает сам.

```bash
uv sync
```

```bash
uv run planer
```

Откройте http://127.0.0.1:8000. Чтобы включить `/admin`, скопируйте
`.env.example` в `.env` и задайте `PLANER_ADMIN_PASSWORD`.

### Docker

```bash
docker compose up -d --build
```

Данные (SQLite) лежат в volume `planer-data` и переживают перезапуск.
Пароль `/admin` берётся из `.env`. Если порт 8000 занят, задайте
`PLANER_HOST_PORT` в `.env`. Контейнер работает под непривилегированным
пользователем; состояние — в `docker compose ps` (healthcheck `/healthz`).

### Доступ с других устройств (HTTPS-туннель)

Для показа и первых тестеров локальный сервер публикуется через
[localhost.run](https://localhost.run): нужен только встроенный в Windows,
macOS и Linux клиент `ssh`, без регистрации и установки. Туннель сразу даёт
HTTPS, поэтому на телефонах работают уведомления, офлайн-режим и установка PWA.

1. Запустите приложение: `uv run planer`.
2. В другом терминале откройте туннель. Порт после `127.0.0.1:` должен совпадать
   с `PLANER_PORT` (здесь 8001; по умолчанию 8000):

   ```bash
   ssh -R 80:127.0.0.1:8001 nokey@localhost.run
   ```

3. В выводе появится адрес вида `https://<id>.lhr.life` — откройте
   `https://<id>.lhr.life/app` на любом устройстве.

Туннель живёт, пока открыт терминал. Если соединение рвётся при простое,
добавьте `-o ServerAliveInterval=30`.

Важно:
- **Адрес временный** и меняется при каждом подключении. Планы хранятся в
  localStorage отдельно для каждого адреса, поэтому на новом адресе тестер
  не увидит планы, созданные на старом. Для постоянного адреса нужен свой
  домен на localhost.run (платно) или деплой на VPS (см. `specs/plan.md`).
- **Приложение доступно из интернета** любому, кто знает адрес. Задайте
  длинный `PLANER_ADMIN_PASSWORD` или оставьте его пустым — тогда `/admin`
  отвечает 404.
- Трафик идёт через сторонний сервис — для реальных пользовательских данных
  используйте VPS с Caddy.
- Cloudflare Tunnel (`cloudflared`) в сети разработки не работает: порт 7844
  блокируется и напрямую, и через VPN. localhost.run ходит по SSH (порт 22),
  поэтому выбран он.

## Как показать на презентации

1. Откройте `/app` → шаблон **«Демо: проспали на 10 минут»**. Скорость времени
   сама станет ×60 (минута плана = секунда).
2. «Начать план» → сообщение об опоздании, пункты сжаты (зачёркнуто старое время).
3. Подождите ~7 секунд → время пункта выйдет: красный отсчёт опоздания,
   строка состояния и заголовок вкладки.
4. Завершайте пункты кнопкой «Закончить» или кликером (→ / PageDown).
5. Итоги → «Увеличить» / «Разбить на подпункты» / «Сохранить».
6. Шаблон **«Демо: утро за минуту»** показывает ранний старт: «Идём с запасом».

Лендинг `/` сам крутит живой пример пересчёта на том же движке.

## Структура

- `src/planer/` — FastAPI: `app.py` (фабрика + CLI), `core/` (настройки, БД),
  `leads/`, `analytics/`, `admin/`, `pages/`
- `frontend/templates/` — Jinja-страницы; `frontend/static/js/engine.js` — движок
  плана (чистые функции), `app.js` — UI планера, `landing.js` — лендинг
- `migrations/` — Alembic
- `tests/` — pytest (API, страницы) и `tests/js/` (движок)
- `specs/` — спека, дорожная карта и критерии проверки спроса; `docs/` — архитектура
- `AGENTS.md` — правила разработки для людей и агентов

## Ограничения MVP

- Планы хранятся только в браузере (localStorage), без аккаунтов.
- Уведомления требуют HTTPS (кроме `localhost`) и разрешения браузера;
  в фоне браузер может задержать их до минуты; на iPhone — только для PWA
  на экране «Домой».
- Тарифы на лендинге — проверка спроса: оплаты нет, кнопка ведёт в форму заявки.
